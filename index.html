Anchored Integrity and Automated Containment
for Clinical Record Stores

Md. Waliul Islam Rayhan · Department of Computer Science & Engineering, Jagannath University, Dhaka, Bangladesh · waliulrayhan@gmail.com

Read the paper (PDF) Source on GitHub Architecture Literature & gap

A clinical record store whose automated containment response rests on evidence a write-path attacker cannot forge: a Merkle log over record digests, its root published to an external RFC 3161 time-stamping authority, and containment triggered by cryptographic mismatch against that published root. This package holds the code, the result files and the data loaders behind every number in the paper.

Running it

pip install -r requirements.txt
python scripts/fetch_data.py        # openly redistributable demos, no credentialing

python scripts/r5all.py             # Tables II and VI, component costs, storage medium
python scripts/r5delay2.py          # Table IV
python scripts/r5token.py           # anchor round trip, connection reuse, chain validation
python scripts/span_ii.py           # Table III

Scripts resolve paths relative to the repository root and honour DATA_DIR, NSLKDD_DIR, RESULTS_DIR, WORK_DIR and IMMUDB_BIN. The baseline and tamper test need an immudb v1.11 binary; the anchor scripts need openssl and outbound HTTPS to a public TSA.

Scope, stated plainly

The guarantee is narrow. A modification that changes stored bytes is detected. Exfiltration, ransomware without a retained comparison, and misuse of legitimate credentials are out of scope — none of them produces a digest mismatch.

Containment needs a verifier outside the attacker's domain. An in-domain attacker who controls the code can suppress its own containment. The prototype here runs the verifier as a separate process on the same host: that shows the detection logic does not depend on store-side state, but it is not a genuinely separate trust domain.

The prefix check does not scale to short intervals at large stores. It recomputes the root over the first k leaves (O(k)); consistency proofs were not implemented. A full audit costs 0.67 s at 106 records — longer than a 0.2 s interval — so the short-interval and large-store results are not combined.

The clinical access population is simulated from MIMIC-IV field structure and admission distributions, labelled by construction. The access layer is password authentication with role-based authorisation and lockout; it is not a zero-trust architecture in the NIST SP 800-207 sense.

Data and licensing

The MIMIC-III and MIMIC-IV demonstration subsets used here are real, de-identified patient records, openly redistributable and requiring no credentialing — only the full MIMIC databases do. NSL-KDD is a third-party benchmark, over two decades old and not healthcare data; it is used only as a reproducible source of network-flow feature distributions. Neither dataset is covered by this package's MIT licence.
